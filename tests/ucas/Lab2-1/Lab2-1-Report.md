# Lab 2.1 Hello, gem5 —— 学号质因数分解实验报告

## 1. 程序设计

**学号转换**：学号 `2026E8013282153`，非数字字符 `E` 替换为 `0`，得到
`N = 202608013282153`（15 位）；反写为 `N' = 351282310806202`。

**程序**：`factor.c`，试除法质因数分解——从小到大枚举除数 `d`，能整除则除尽并打印，
直到 `d*d > n`，剩下的 `n` 即最大质因子。静态编译两种输入：

```bash
gcc -O2 -static -DNUMBER=202608013282153ULL -o factor factor.c
gcc -O2 -static -DNUMBER=351282310806202ULL -o factor_rev factor.c
```

**分解结果**（本地已验证）：

| 输入 | 分解结果 | 试除上界 sqrt(剩余大因子) |
|---|---|---|
| 学号 202608013282153 | **37 × 5475892250869** | √5475892250869 ≈ 2,340,297 |
| 反写 351282310806202 | **2 × 277 × 634083593513** | √634083593513 ≈ 796,297 |

试除法在除尽小因子后继续从当前 `d` 枚举，循环终止条件是被除后的 `n` 的平方根，
因此学号输入需要约 **234 万**轮循环，反写输入只需约 **80 万**轮——学号输入运算量约 3 倍。

**配置脚本**：`lab21.py`（以 `configs/learning_gem5/part1/simple.py` 为基础，
把二进制路径 / CPU 型号 / 频率 / 内存型号参数化，其余不变：512MiB、timing 模式、SE）。

## 3. 分析

### 3.1 学号 vs 反写：1.459s vs 0.503s（约 2.9 倍）
试除法在除尽小因子后循环终止于剩余大因子的平方根：学号输入最终剩余
5475892250869，需枚举到 d≈2.34M；反写输入剩余 634083593513，只需枚举到
d≈0.80M——运算量之比 2.9，与两种配置的模拟时间之比完全一致。hostSeconds
（39.8 vs 13.4）同比例缩短：TimingSimpleCPU 逐条解释执行，宿主机开销与
动态指令数（23.5M）成正比，与微架构参数无关。

### 3.2 TimingSimpleCPU vs MinorCPU：模拟时间 −20%，实际时间 ×7.4
- **模拟时间** 1.459→1.162：MinorCPU 是 4 级流水（fetch/decode/execute/writeback），
  相邻指令的流水段重叠，循环控制、地址计算等短指令的延迟被除法长延迟掩盖，
  同样的动态指令数总周期数更少；
- **实际时间** 39.8→294.8s：MinorCPU 逐流水段建模（事件队列更密），
  每条指令的模拟开销远大于 TimingSimple 的"查延迟表"模型。
  这正对应 stats 中 simSeconds 与 hostSeconds 口径的区别——模拟的计算快了，
  但算得更慢。

### 3.3 频率 1GHz→2GHz：模拟时间只降 10%，并非减半
CPU 周期相关的部分（除法、ALU、流水段推进）随频率翻倍减半，但**内存延迟以
纳秒计**，不受 CPU 时钟影响：TimingSimple 是阻塞式模型，每次访存都要等
DRAM 时序走完。程序每条迭代约 2 次访存，模拟时间由访存等待主导——2GHz 只把
~20% 的 CPU 时间压缩一半（1.459→1.311），剩下的是内存墙。hostSeconds 不变
（模拟的事件数量一样，与频率无关）。

### 3.4 DDR3_1600→DDR3_2133：模拟时间 −4.2%
程序是计算主导（寄存器内的除法循环），访存只有每迭代的栈操作等少量访问，
内存提速只作用于这一小部分：1.459→1.397。hostSeconds 不变。
对比 3.3：该负载下"提内存"和"提频率"都只能小幅改善——真正的时间大头在
阻塞式访存的绝对延迟上，这与现代 CPU 用乱序+多级缓存隐藏延迟的动机一致。
